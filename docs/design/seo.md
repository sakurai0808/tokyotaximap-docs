# SEO・AEO（検索とAIでの見つかり方）

## 目標（2026-11-27決定）

- このサイトの目標は、ドライバーと乗客が正確に早く情報にたどり着くこと。SEO・AEOは、その入口の1つとして扱う
- 最初に大事にする読み手は、仕事に出たばかりのドライバー
- 検索（Googleなど）からの来訪は、主要な入口にする
- AI（ChatGPT検索、Perplexity、Google AI Overviewなど）の回答では、サイトが引用・紹介されることを目指す。そのため、正確な答えを拾いやすい形で書く
- 成功の判断は、次の3つで見る
  1. サイト内の検索とピンマップが使われているか（Google Analytics）
  2. 検索からのクリック数（Google Search Console）
  3. 目的の記事に着き、読み終えたか（Google Analytics）

## 決めたこと（2026-11-27）

| 項目 | 決定 |
| --- | --- |
| 答えの一文（`summary`） | 全記事に書く（ピンのない記事も含む）。検索結果の説明文（`description`）と、AIが引用する答えの候補にする |
| 構造化データ（JSON-LD） | `Article` だけ入れる（公開日・更新日を機械に伝える）。`FAQPage` は入れない |
| AIのクローラー | すべて許可する（学習用も含む）。依頼者の選択。学習用の読み取りを拒否する方針に変えるときは、`robots.txt` で変える |
| タイトル | 検索されやすい言葉（地名、施設名、出入口など）を入れるように、試験版のタイトルを直す。直し方は記事ごと |
| URL | 記事のURLは、WordPressと同じ `/{slug}/` のまま引き継ぐ。記事以外の旧URL（カテゴリ・タグ・固定ページなど）は、同じURLで必要なものを作る（転送はしない） |
| OGP画像（SNS共有の画像） | サムネイル（`thumbnail`）を使う。記事ごとの共有用画像は作らない |
| 廃止された出入口 | 検索と一覧に残す（[content-model.md](content-model.md) の「廃止された出入口の記事」） |
| noindex | 試験版は付けたまま。本番の公開のときに外す（[infrastructure.md](../engineering/infrastructure.md)） |
| サイトマップ | `sitemap.xml` を自動で作る。本番の公開のときに、Search Consoleに登録する |
| `robots.txt` | 公開する。サイトマップの場所を書く |
| `canonical` | 各記事に、その記事の正規のURLを書く |
| タイトルの形 | `記事のタイトル | 東京都心タクマップ` |
| 404ページ | 存在しないURLで表示する。検索結果に載せない |
| 運営者情報 | 出す。プロフィールのページを作る（名前・プロフィール・連絡先）。検索の評価で、運営者の信頼性が見られるという考え方に沿う（私の理解。実際の評価の基準は確かめていない） |
