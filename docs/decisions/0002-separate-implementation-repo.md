# ADR 0002: 本実装は別のリポジトリにする

## ステータス

採用（2026-11-25）

## 決定

- 本実装（公開するサイト）は、このリポジトリとは別の新しいリポジトリで作る。
- このリポジトリ（`tokyotaximap-docs`）は、仕様・設計・ログを含めて試行錯誤を残す場所とする。PoC（`poc/`）もここに残す。
- 試験版（`pages.dev`）は、本実装の準備が整うまで `poc/` から配る。

本実装のリポジトリに入れるもの: サイトのコード、記事（`content/articles/`）。
入れないもの: `docs/`、`logs/`、`migration/`（作業メモ）。

## 理由

- このリポジトリの役割は、仕様と試行錯誤を残すことである。本番のコードと同じ場所に置くと、役割が混ざる。
- このリポジトリは公開（PUBLIC）である。作業の経緯を残す場所と、サイトのコードを置く場所を分けると、公開する範囲を別々に決められる。
- 本番のリポジトリは、サイトを作るためだけのものになり、見通しがよくなる。手間はかかるが、それを受け入れる。

## 検討した案

- **同じリポジトリで `poc/` を育てる**: 本番のコードと試行錯誤が同じ場所に入り続ける。公開の範囲を分けられない。
- **同じリポジトリに本実装のフォルダを並べ、あとで切り替える**: 切り替えまでの間、同じものを2か所で持つことになり、どちらが正かを混同しやすい。

## 影響

- Cloudflare Pages: 本実装の準備が整ったら、新しいリポジトリを接続し、Root directory と Build watch paths を新しいリポジトリに合わせる。手順は [インフラ設計](../engineering/infrastructure.md) に書く（作業のときに書く）。
- 試験版: 準備が整うまで、今の `poc/` から配る。

## 未決定

- 本実装のリポジトリを公開にするか、非公開にするか
